# 중복 요청 방지와 주문 취소

## 사용법

Update-Dashboard.cmd 실행 후 http://localhost:8080/ 를 새로고침합니다. API 시작 시 요청 기록 테이블을 추가하며 기존 주문·재고를 초기화하지 않습니다. 최근 주문 목록의 직접 생성한 결제 완료 주문에 `주문 취소` 버튼이 나타납니다. 취소하면 상태·재고·현황 집계가 갱신됩니다. 실험용 과거 주문은 취소할 수 없습니다.

주문 응답을 확인하지 못하면 `같은 주문으로 재시도`를 누릅니다. 같은 탭을 새로고침해도 sessionStorage의 요청 번호와 입력값을 재사용합니다. 응답 확인 전에는 입력을 잠급니다. 탭을 닫거나 저장소를 지우면 이 재시도 정보는 사라집니다. 별도 탭의 새 주문은 별도 요청입니다.

## 설계와 대안

| 변경 | 이유 | 대안 | 검증 |
|---|---|---|---|
| 고객+요청 키 복합 기본키 | 서버 프로세스가 달라도 DB가 중복 요청을 직렬화 | 메모리 캐시는 재시작·다중 서버에서 누락 | 16개 동시 요청이 같은 주문 ID 반환 |
| 요청 기록·재고 차감·주문 삽입 한 트랜잭션 | 성공 기록과 주문이 함께 커밋되어 응답 유실 후 재조회 가능 | 요청 기록을 먼저 별도 커밋하면 미완료 키 복구 필요 | 품절 실패 후 키 기록 없음, 기존 재고 롤백 테스트 |
| ON CONFLICT DO NOTHING 후 별도 SELECT | READ COMMITTED에서 경쟁 트랜잭션 커밋 후 새 스냅샷으로 결과 조회 | 단일 문장 CTE는 경쟁 시 스냅샷 때문에 결과를 못 볼 수 있음 | 동시 생성과 재시도 ID 일치 |
| 동일 키의 상품·수량 비교 | 다른 요청을 이전 성공으로 오인하지 않음 | 키만 비교하면 변경된 수량을 무시 | 수량 변경 409 |
| 취소 대상 주문 FOR UPDATE | 상태 확인부터 복원까지 직렬화 | 상태 조회 후 무조건 복원하면 중복 증가 | 16개 동시 취소 중 최초 1개만 복원 |
| 주문 상태 변경과 재고 증가 한 트랜잭션 | 부분 취소 방지 | 비동기 복원은 재처리·보상 설계 필요 | 재고 10→8→10 및 반복 취소 검증 |
| 추가 전용 마이그레이션 | 기존 데이터를 보존하며 업데이트 | 재시드는 주문·재고 초기화 | 별도 DB에서 기존 데이터 유지, 새 설치 seed에도 테이블 생성 |

## HTTP 계약

- `POST /orders`: 기존 JSON 입력에 선택적 `Idempotency-Key` 헤더. 영문·숫자·밑줄·하이픈 8–100자. 화면은 UUID를 생성한다. 최초 성공 201, 재시도 200과 `replayed:true`, 다른 상품·수량 409, 키 형식 오류 400.
- 키를 생략하는 기존 API/벤치마크 호출은 기존 동작을 유지하며 중복 방지를 보장하지 않는다.
- `POST /orders/{id}/cancel`, JSON `{ "customer_id": 700002 }`: 최초·반복 취소 모두 200. 최초만 재고 복원. 고객 불일치·없는 주문 404, 과거 실험 주문 409.
- 취소된 주문의 생성 키를 재사용해도 새 주문은 생성하지 않는다. 원래 주문 ID를 돌려주며 현재 상태는 목록에서 확인한다.
- 실패 요청은 롤백되어 키가 남지 않는다. 키 만료는 아직 없으며 실험 초기화/주문 삭제 시 제거된다.

## 실제 검증 기록

2026-09-12, 별도 Windows PostgreSQL 18.4 검증 DB(port 55439), Node.js 로컬 API(port 8083)에서 실행했다. Docker 사용자 데이터는 변경하지 않았다.

- `npm test`: 단위 테스트 9개 통과.
- `DASHBOARD_URL`을 지정한 `npm run test:checkout`: 동시 요청 16개→주문 1개, 동시 취소 16개→복원 1회. 키 충돌·형식·잘못된 고객·품절 롤백·과거 주문 보호·취소 후 생성 재시도 통과. 전용 테스트 상품과 주문만 만들고 제거한다.
- 같은 검사에서 HTTP 생성 201·재시도 200·충돌 409·취소 200 확인.
- `node test/dashboard-http.mjs`: 정적 자산·조회·기존 측정 기록·960개 CSV 표본 검사 통과.
- 브라우저에서 고객 700002 주문 #300134 생성 및 취소 성공 메시지 확인. 검증 DB에 취소 기록을 남겼다.
- 네트워크 응답 유실과 새로고침 후 재시도 UI는 자동 장애 주입으로 검증하지 않았다. 서버의 동일 키 재시도는 동시성/HTTP 검사로 검증했다.
- 새 Docker 이미지 실행 검증은 사용자가 Update-Dashboard.cmd를 실행한 뒤 로그로 확인한다. 성능 수치는 새로 측정하지 않았다.

## 종료 코드 판정 수정 — 2026-09-12

기존 실행 기록의 exit_code=null을 조사해 실제 버그를 재현했습니다. 함수 내부에서 `$LASTEXITCODE=$null`을 만들면 로컬 변수가 네이티브 명령이 갱신하는 전역 종료 코드를 가립니다. 성공 명령도 null로 읽어 실패할 수 있었습니다. CI와 백업 실행 함수 모두 `$global:LASTEXITCODE`를 명시적으로 초기화하고 읽도록 수정했습니다. 이 버그 때문에 기존 null 기록만으로 Docker 명령 자체가 실패했다고 단정할 수 없습니다.

대안은 Process API로 ExitCode를 받는 방식이지만, 기존 스트림·인수 처리를 유지하는 최소 수정으로 해결했습니다. 실제 함수 정의를 로드하는 `test/powershell-runner.ps1`을 Windows PowerShell에서 실행해 종료 코드 0 허용, 7 거부, 없는 실행 파일의 이전 코드 재사용 방지를 확인했습니다. Docker를 대체 실행한 테스트가 아니므로 전체 DB 검증의 성공 증거는 아닙니다. GitHub Actions에도 별도 Windows 검사 작업을 추가했습니다.

에이전트의 직접 Docker 실행은 별도로 접근 거부되는 것을 확인했습니다. 수정된 Test-Portfolio.cmd와 Backup-Restore.cmd의 전체 결과는 사용자 실행 후 다시 확인해야 합니다.

## 실행과 결과

Windows에서 Docker Desktop을 실행한 뒤 `Test-Portfolio.cmd`를 실행합니다. 운영 서비스 재빌드나 재시드는 필요하지 않습니다. 처음 실행할 때는 테스트 이미지 빌드에 시간이 걸립니다.

실행마다 `results/ci/<실행시각_임의값>/report.json`과 단계별 로그를 만듭니다. `status=passed`와 `cleanup=removed`를 함께 확인합니다. 테스트가 실패하거나 정리하지 못했으면 실패로 반환합니다. 컨테이너 로그는 가능한 경우 실패 후에도 수집합니다.

별도 `compose.ci.yaml`을 사용하며 임의 이름 `portfolio-test-<GUID>`로 프로젝트를 생성합니다. 호스트 포트를 공개하지 않고 운영 볼륨을 마운트하지 않습니다. DB는 테스트 컨테이너의 tmpfs에 저장하며 종료 시 제거합니다. 기존 localhost:8080 서비스와 함께 실행할 수 있지만 CPU·메모리·디스크 부하는 공유하므로 성능 측정과 동시에 실행하지 않습니다.

## 검사 순서

1. Compose 구성 확인과 이미지 빌드.
2. 테스트 DB 기동과 단위 테스트 13개.
3. 1만 건으로 초기화하는 기존 통합 테스트: 초과 판매 재현, 개선 후 보존식, 롤백, 인덱스 결과 동일성, 배타 잠금.
4. API 기동 후 중복 생성·취소의 동시성 및 HTTP 검사.
5. 실제 잠금 관측과 복원 SQL의 원본 DB 보호 검사.
6. HTTP 자산·상태·요청 ID 검사. CI에는 과거 측정 파일이 없을 수 있으며 빈 상태를 정상적으로 허용한다.
7. 실제 pg_dump→별도 DB 생성→pg_restore→복원 데이터/쓰기 검사.
8. 로그 수집과 이 실행에서 만든 테스트 프로젝트만 정리.

이 파이프라인은 기능·정합성 검사입니다. 1만 건에서 통과했다고 30만 건 성능 수치를 갱신하지 않습니다. 워크플로에는 성능 임계값이나 성공 배지를 하드코딩하지 않았습니다.

## GitHub 적용

이 `postgres-order-lab` 폴더의 **내용을 저장소 최상위**에 넣으면 `.github/workflows/validate.yml`이 push·pull request·수동 실행에 반응합니다. 상위 폴더 통째로 올리면 워크플로 경로와 작업 디렉터리를 조정해야 합니다. 이번 작업에서는 GitHub 저장소 생성·업로드·실행을 하지 않았습니다.

GitHub 호스팅 Ubuntu 러너에서 같은 PowerShell 스크립트를 실행합니다. 결과 로그는 성공/실패와 관계없이 가능한 범위에서 artifact에 14일 보관합니다. 토큰 권한은 contents:read입니다. 외부 배포·클라우드 자원 생성·비밀값 설정은 포함하지 않습니다. 작업의 20분 제한을 초과하거나 러너가 강제 종료되면 스크립트의 finally 정리는 완료되지 않을 수 있습니다.

구성 시 확인한 공식 자료: [checkout](https://github.com/actions/checkout), [upload-artifact](https://github.com/actions/upload-artifact).
